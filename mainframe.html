01

Translating COBOL is nearly free now. Getting it wrong still costs what it always did.

On February 23, 2026, an AI lab described Claude Code reading and translating COBOL, and IBM had its worst trading day since 2000.1 By then AWS was already offering its own mainframe transformation agent at no charge.2 Turning COBOL into Java stopped being the hard part.

What changed is how it goes wrong. When people translated by hand, mistakes usually showed up right away because the code wouldn't run. AI-translated code runs fine and passes the tests the AI wrote for itself, and it can still drop a rule your business depends on. It can also add a rule nobody asked for, which is even harder to spot (Exhibit B).

Every record tells a different story. The real data settles it.

On a real mainframe, the records disagree. The code says one thing, the field layouts suggest another, the job setup a third, and the real data shows something else. The engineer who knew why retired years ago. A tool that quietly picks one version hides the problem, so I write down every disagreement as a finding.

1 · THE CODE

"Divide the rate by twelve."

Says what happens. Never says what the number means.

2 · THE FIELD LAYOUT (COPYBOOK)

"Seven digits, five after the point."

Fits 0.03500 and 3.50000 equally well. Doesn't say which.

3 · THE FILE SETUP (JCL)

"This file is line sequential."

One wrong line here made two AIs read numbers as text. See Exhibit D.

Asked to translate a monthly interest program, one AI started adding to a year-to-date total that the original program never touches.

Every claim in it points to data you can reproduce on demand. It answers the questions examiners and risk teams already ask about software an AI helped write.

A note on the rules. U.S. banking guidance on model risk was rewritten in April 2026 and, for now, doesn't cover generative AI.7 Until that's settled, the report covers what examiners already look for: testing, results anyone can reproduce and a named person who signs off.

05

What this does not prove.

  • How the system handles data that never showed up in testing. I report what was covered and never imply more.
  • What the business meant, where nobody can say anymore. Those fields go on the unclear-fields list with a named owner, not a guess.
  • Speed, capacity or overnight batch timing. Those need their own tests, and the report says so.
  • Anything outside the systems we agreed on.

Anyone who promises "100% equivalence" without this list is promising something no one can check.
