# How this site is built

Jekyll skips folders that start with an underscore, so nothing in `_build/` is served.

1. `canvas/` holds the three design pages (`.dc.html`), the same files as the claude.ai Design canvas.
2. `node dump.js canvas vals.json` evaluates each page's `renderVals()` for every interactive state.
3. `python3 build.py canvas out vals.json` writes `index.html`, `local.html`, `mainframe.html`, `404.html`, `sitemap.xml`, `robots.txt`, `favicon.svg`, `CNAME`.
4. `python3 enhance.py out` adds what the canvas doesn't carry: the packed-decimal decoder (`comp3.html`), tap-a-number sources on the receipts, the raw-to-reel timeline, the intake quiz, drop-in hours, and stand-ins for the photo.
4b. The four free tools (`shotlist.html`, `captions.html`, `receipt.html`, `scaler.html`, added Nov 8, 2026) are written by `tools/`: `cd tools && python3 shotlist.py ..` (same for `captions.py`, `receipt.py`, `scaler.py`) regenerates the template in `_build/`, with the shared header and footer from `tools/chrome.py`. Edit the `.py` file, never the generated page. `enhance.py` copies them into `out/`, along with `assets/bird-league-then-now.jpg` for the Bird League card on `work.html`.
   The voice checker (T-35, Nov 21, 2026): `cd tools && python3 voicecheck.py ..` writes `voicecheck.html` the same way. A visitor pastes words written with AI; the page marks the sentences that read as machine-made, says why and what to put there instead, all in the browser (no fetch, no Worker, no storage, nothing in the address). Its checks come from Josef's voice harness; `window.voiceCheck(text)` returns the sentences and their marks for tests. Not to be confused with `voice.py`, an older build pass. It is listed from day one: `TOOLS` in `tools/chrome.py` (order: checkup, voice checker, receipt, shot list, caption fitter), `enhance.py`'s tool lists, the sitemap in `build.py`, the first free tool card on `work.html` (which `local.html` reads), and `tools/og.py`'s pages. A new page needs its share card before `enhance.py` will copy it in: put any card at `assets/og/<page>.png` for the first build, run `tools/og.py out`, then rebuild from step 4.
4c. Share cards (Nov 9, 2026): `python3 tools/og.py out` draws a 1200 by 630 PNG per public page into `assets/og/` from each finished page's `<h1>` and meta description, with the fonts in `assets/fonts/` (OFL). It reads the pages after steps 5 and 6, so rerun it after a build whenever a headline or description changes, then rebuild from step 4. `enhance.py` copies the cards to `out/og/` and adds the `og:image` and `twitter:card` tags (the four tools get theirs from `tools/chrome.py`). Copy `out/og/` to `og/` at the repo root along with the pages.
   The look (T-40, Nov 22, 2026): the chart style, a small poster of the page's top. Chart paper, the brand row as the live header (mark, accent dot, "Dragoman's Journey" in Newsreader), the headline in the face and weight of the page's own `<h1>` with its colored and pen-marked words as the live page shows them, the subhead in Barlow, an ink "Free tool" pill on the free tools, and an accent bar (orange, blue on the Mainframe pages). The marks and colors are read from the repo-root copy of each page, so build and copy the root first; the run stops if a text color pair falls below WCAG AA.
4d. The Studio (Nov 11, 2026): `cd tools && python3 studio.py ..` writes `studio.html` from `studio.json` (the products) and `shipped.json` (the build log, newest first), with the header and footer from `tools/chrome.py`. Every word comes from those two files. A product with a `gate` doesn't show, and neither do its log lines; log lines older than 120 days drop off; the count over the log is counted from the lines that show, as of the day `studio.py` runs. `enhance.py` copies the page in and adds "Studio" to every header (before "Free tools") except the three Mainframe pages (T-16). It stops the build if either JSON file changed since `studio.py` last ran.
   Product pages (T-09, Nov 11, 2026): `studio.py` also writes `studio-<id>.html` for each product with no gate and a join list (today `studio-birdleague.html` and `studio-deepcuts.html`): the product's name, status, what, proof, image, every log line of its own that shows, and one join box. Each card links to its page ("More on <name> →"), and each page links back ("← The Studio"). When a gate clears (the album), its page, sitemap line and share card appear on the next build: run `studio.py`, build, run `tools/og.py out`, then rebuild from step 4 so the new card is copied in.
   Join lists (T-10, Nov 11, 2026): every join button is a small form, an email field and the list's button. It posts `form: "list"` to the intake Worker (`worker/intake.js`, the same address as `start.html`), says "You're on the list" when the Worker answers ok, and otherwise opens the old mailto ("List: <product name>"). The line under a product page's box is the list's `line` in `studio.json`. After any change to `worker/intake.js`, make the same change in `worker/intake.deployed.js` (the one-line file Josef pastes into Cloudflare) and run `node worker/test_intake.mjs`, which checks both with no network.
   To log a ship: Claude adds one line at the top of `shipped.json` (`date`, `project`, `line`: plain words for a stranger, no client names), runs `studio.py`, rebuilds from step 2, tests, and commits. Josef never edits it. A line stays only if a stranger can picture what changed: no build number without what a person can now do. A new `project` needs a product in `studio.json` with the same `id` (its name becomes the line's label), or the build stops and names it. Rerun `studio.py` before any push, so the count and the 120-day drop-off are counted from that day.
4e. Website checkup (T-04, Nov 12, 2026): `cd tools && python3 checkup.py ..` writes `checkup.html`, the fifth free tool (once it is live, the work page card, the `local.html` tools section and every tool's "More free tools" line list it). The page asks the `dj-checkup` Worker (`worker/checkup.js`, separate from intake) to fetch an owner's page and answer with plain facts; the page turns them into the two report cards. `CHECKUP_URL` at the top of the page's script is empty until the Worker is live: while it is, the page says "Coming this week" and shows no box, and (T-20, Nov 15, 2026) no other page links to it: the work card, the `local.html` card, the "More free tools" mention and the `sitemap.xml` line are all left out. Every build script reads that one value through `tools/chrome.py` (`checkup_url()`); nothing else holds a copy. When Josef pastes the Worker's address, set it, rerun `checkup.py`, rebuild from step 2 and test: the links, the card and the sitemap line come back on their own. **It is set (T-36, Nov 21, 2026): `https://dj-checkup.stephens-josef.workers.dev/`, so the checkup is live and the older checks read the live state (`CK_LIVE`, `CK_ADDR`, `ck_test_url()` in `test_new.py`).** `node worker/test_checkup.mjs` checks the Worker's safety rules, link classifier and AI checks with no network (`test_new.py` runs it). The AI crawler names in `checkup.js` come from each company's own docs; reread them before changing the list.
5. `python3 plain.py out` runs the plain-language pass (Oct 26, 2026) over the finished pages. Every edit must hit at least once.
6. `python3 intent.py out` runs the intent pass (Oct 28, 2026): every word on a page is there on purpose for a specific reader. Each edit carries its line ID from the audit in the vault (`Claude outputs/2026-10-28-intent-audit-dragomans-journey.md`) and must match exactly, or nothing is written.
6a. `python3 voice2.py out` runs the voice pass (Nov 12, 2026), after `intent.py` and before `final.py`: Josef's own words, approved line by line; the record is in the vault at `Claude outputs/dragomans-journey/voice-pass-2026-11-12.md`. Each edit carries its ID (V1, V2, ...) and must match exactly once, or nothing is written and the build names the edit that missed. Later pages add their edits to this same file.
6b. `python3 final.py out` runs last, after `voice2.py` (Nov 11, 2026). It reads the finished pages and adds one `<script type="application/ld+json">` before `</head>` on `local.html` (the business, its offers and its FAQ) and `mainframe.html` (the Mainframe Route and its priced steps). Every name, price, description and FAQ line is read from the page, so it always matches what the page says; if a price can't be found, the build fails and names it. It isn't in `enhance.py` because `intent.py` counts exact matches, and a second copy of a page's words in a script tag would break that. `tools/og.py` is not affected: it reads only each page's `<h1>` and meta description, which `final.py` doesn't touch.
   The visit counter (T-12, Nov 11, 2026) lives here too: `CF_BEACON_TOKEN` at the top of `final.py`. While it is empty, nothing is added. When it holds the token from Cloudflare's Web Analytics snippet, `final.py` first adds one sentence to the `local.html` FAQ answer "What do you do with our data?" (so the FAQ data carries it too), then puts Cloudflare's beacon just before `</body>` on every page except `comp3.html` (its address holds pasted bytes on purpose). `start.html` clears its own `#` after reading it, so text typed on the quiz or the receipt never sits in the address the beacon can see.
6c. `python3 theme.py out out-themed` runs last, after `final.py` (T-32, Nov 20, 2026): the chart style. It writes a themed copy of every page in `out/` to `out-themed/` (every other file copied as it is) and leaves `out/` exactly as it was, so the older checks keep testing what they always tested. **The repo root is copied from `out-themed/`, not from `out/`.** The old palette stays in the sources; `theme.py` is where the new one lives: every color in a style attribute, a `<style>` element, an SVG paint attribute and the style strings the pages' scripts apply is rewritten by its role (background, text or line, and whether it sits on something light, an accent fill, or something that stays dark: the footer, the closing call box, pills and dark buttons). The accent stays today's orange (Josef, Nov 19, 2026); the Mainframe pages use blue. Big Shoulders Display becomes Barlow Semi Condensed, Instrument Sans becomes Barlow, and uppercase is off. It also draws the ring around each page's one next step (`RINGS`) and the dashed route line along each step list (`route_css()`), and (T-34, Nov 20, 2026) the pen underline: the source that writes a headline marks its few marked words `class="pen"`, and `pen_css()` adds the one definition to any page that uses it, orange (blue on the Mainframe pages), lighter on something that stays dark (`pen-ink`). Headlines never switch to italic. A color it doesn't know stops the build and names it: give it a role in `theme.py` and list it in the item's Receipt. `_build/DESIGN.md` is the design record, copied from the vault; where it says magenta, the site uses the orange.
7. Serve `out/` locally and run `test_site.py` and `test_new.py`. `test_new.py` also runs `node worker/test_intake.mjs`. The T-32 section serves `out-themed/` on its own port and checks the themed pages against `out/`.

## Tests

`test_new.py` is split into sections, one per `# ----------------` header, each a function with a short id (T-31, Nov 19, 2026). Build `out/` first (the steps above); the test scripts build nothing.

- **Everything, in parallel:** `python _build/run_tests.py`. It serves `out/` on a free port and runs the sections on CPU cores minus one worker processes (at most 6), each with its own browser, longest first by the last run's times. Each section prints one line when it finishes (its id, its check count, its failures, its seconds), each failing check prints the moment it fails, and the end says `<passed>/<total> passed in <m> min <s> s (<N> workers)` and lists every failure. The full result, every check in the serial order, goes to `dj-test-results.json` in the system temp folder.
- **One or two sections:** `python _build/run_tests.py --only T-30,T-18`. A section run alone builds what it reads from an earlier one (`studio_log()`, `sample()`, `thin18()` near the top of `test_new.py`).
- **Serially:** `python _build/run_tests.py --jobs 1`, or `test_new.py` as before: serve `out/` and run `python _build/test_new.py http://localhost:8765/ <shots folder>` (add `--only <ids>` for some sections, `--results <file>` for the JSON). Both print the same per-section lines.
- **The ids:** `python _build/run_tests.py --list` prints them with each one's time from the last run. In file order: `decoder`, `local-page`, `start-briefing-dropin`, `work-case-study`, `mainframe`, `free-tools`, `share-cards`, `free-tools-findable`, `machine-facts`, `visit-counter`, `studio-log`, `studio-pages`, `join-lists`, `checkup`, `intent-pass-2`, `T-17`, `T-18`, `T-19`, `T-20`, `T-21`, `T-22`, `T-23`, `T-24`, `T-25`, `T-26`, `T-27`, `T-29`, `T-30`, `T-32`, `T-33`, `T-34`, `T-35`.
- **Browser:** the Linux Chromium in `/opt/pw-browsers` where it exists, otherwise Playwright's own installed Chromium (`python -m playwright install chromium`). One file runs on Windows and Linux; no Windows copy is needed.
- **Fonts:** with `FONT_DIR` present (Linux), the fonts come from it, as before. Without it, they are recorded once and replayed: the first request for each Google Fonts address is fetched live and saved, keyed by its full URL, in `dj-test-fonts` in the system temp folder (outside the repository); every later request and every later run is served from there with the same body and content type, so no run waits on Google. The first line says `fonts: cache (n files)` or `fonts: recording`. Delete that folder to record fresh.
- **Older checks and later items** (T-33, Nov 20, 2026): an older check that compares a page with an earlier build reads it through that item's "un" helper (`un30()`, which calls `un33()`), so it keeps proving exactly what it proved. `un33()` reads `_build/t33_undo.json`: T-33's changes in `out/`, each beside origin/main's lines, for the normal build and for a build with the checkup address set. The T-33 block proves it against origin/main's root. If a later item rebuilds a page T-33 changed, regenerate that file from a build of origin/main before the item and the new build. T-34 (Nov 20, 2026) does the same with `un34()` and `_build/t34_undo.json` (its changed lines in `out/` beside origin/main's): `un30()` and every older read through `un33()` take T-34 out first, and the T-34 block proves it against origin/main's root. T-35 (Nov 21, 2026) adds `un35()` and `_build/t35_undo.json` the same way (the Studio pages' build-day lines stay out of it; `stamp27()` folds them), plus `un35_file()` for the one share card it redrew (`og/index.png`, read as origin/main had it) and `T35_NEW_FILES`, the files it adds, which the older share-card listings leave out.
- **A new item's checks** go in a new section function at the end of `test_new.py`, after the last one: a `# ---------------- T-NN (date): what it does` header, then `@section('T-NN')` and `def s_t_nn():`. Anything a later section will read from it goes above the sections, with the shared helpers, or in a function that builds it on first use.
- The other gates run on their own: `python _build/test_site.py <base> <shots folder>`, `node _build/worker/test_intake.mjs`, `node _build/worker/test_checkup.mjs`.

Settings at the top of `enhance.py`: `DROPIN_DATE`, `DROPIN_PLACE`, `LINKEDIN`. Fill them in and rebuild. Setting at the top of `final.py`: `CF_BEACON_TOKEN` (step 6b).

## Hosting

Today GitHub Pages serves the repository root. Cloudflare hosting is built but not switched on yet (T-15, Nov 12, 2026; the switch steps are in T-15's Receipt in `trip/QUEUE.md`).

- `sh _build/publish.sh` makes `dist/`, exactly the public site: every git-tracked file outside `_build/`, except `CNAME`, `wrangler.jsonc`, and any name starting with a dot or an underscore. It fails loudly if `dist/` would be empty or if anything from `_build/` lands in it. `dist/` is in `.gitignore`.
- It also writes `dist/_redirects`. Cloudflare reads that file and never serves it. The first line, `/ /index.html 200`, lets `/` find the home page. Then comes one line per page, like `/local /local.html 200`. GitHub Pages answers `/local` as well as `/local.html`, and these lines keep those short addresses working after the switch. A `200` line serves the page at the short address; it doesn't redirect. The lines are made from the git-tracked `.html` files at the root, so a new page gets its line on its own. `index.html` (the `/` line covers it) and `404.html` get none.
- `wrangler.jsonc` at the root: a Worker named `dragomans-journey` that serves `./dist` and runs no script. `html_handling` is `none`, so `/local.html` answers at that exact address instead of redirecting to `/local`. `not_found_handling` is `404-page`, so a missing address gets `404.html` with status 404. `"previews": {}` gives every branch other than `main` its own preview address. It holds no secret.
- To check it locally: `sh _build/publish.sh`, then `npx wrangler dev --port 8765`, then run `test_new.py` against `http://127.0.0.1:8765/`.
- Forms don't send from a preview address or from the Worker's own `workers.dev` address, because the intake Worker only accepts the real site's address. That's expected.
