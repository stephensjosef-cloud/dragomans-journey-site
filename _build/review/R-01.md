## Angle 1 · The full walk

**Method:** a script (`walk.py`) loaded each of the 19 pages at 320x640, 390x844 (both mobile with touch) and 1440x900, twice each: once waiting for `document.fonts.ready`, and once with every fonts.googleapis.com and fonts.gstatic.com request aborted. Each page was scrolled through to trigger lazy content. That is 114 full-page screenshots, plus, for each run: scrollWidth against clientWidth, the deepest elements past the right edge, overlapping text-node boxes, images with `naturalWidth 0`, 4xx/5xx responses and console errors. A follow-up pass (`noimpact.py`) repeated 320 and 390 with fonts blocked **and** Impact unavailable, as on Android and Linux.

**Result:**

| | Real fonts | Fonts blocked (Impact present: Windows, Mac, iPhone) | Fonts blocked, no Impact (Android, Linux; simulated) |
|---|---|---|---|
| Sideways scroll | none on any page | index 320: 323 (footer line); local 320: 322 | local 390: **444**; local 320: **367**; index 320: 323 |
| Overlapping text | none (see note) | none | not checked |
| Failed images | none | none | not checked |
| Console or page errors | none | only the aborted font requests | none |

- **Known lead (local.html, h3 "The Blueprint&nbsp;·&nbsp;$1,500"):** confirmed at 444 and 367 only with web fonts blocked on a device without Impact. With real fonts there is no sideways scroll, though the heading's text is already wider than its box (331 px in 324 at 390; 266 in 254 at 320). See finding 16.
- **Overlap note:** the probe flagged studio (the chart's hidden "Oct 5: 3"-style labels), scaler (a visually hidden table header) and work (tight line boxes on the big heading). All three were checked on cropped screenshots and are false positives.
- The probe skipped sticky and fixed elements, which is why it did not catch the receipt's sticky paper covering the buttons (finding 4). R6 found that, and hit-testing confirmed it.
